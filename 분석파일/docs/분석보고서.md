## 3. 에셋 암호 (meta)

- 키: `global.passwd = "Fp1OUltT6n"` — `gml_Script_launch_set_test`에 평문.
- 알고리즘(`buffer_encode_ext`, 커뮤니티 스크립트 file_fast_crypt_ultra 계열):
  - `H(s) = md5_unicode(s) + sha1_unicode(s) + md5_utf8(s) + sha1_utf8(s)` (hex 144자)
  - `kh = H(key); kh2 = H(kh); kh = kh + kh2` → 144바이트 키 배열
  - 바이트마다 `dec = ((b ^ xs ^ k) + bs − k) mod 256`, xs 1→5000 순환(넘으면 키 재해시), bs는 키 짝홀로 ±1(1..255 순환)
  - ⛔ **버그 호환 필수**: 키 hex를 `hex_to_dec_fast`로 푸는데 이 함수는 대문자만 맞다(`((ord+4) mod 23 − 6) & 15`). 해시는 소문자라 `a..f`가 `3..8`로 풀린다. 정상 hex로 풀면 「거의 JSON 같은 쓰레기」가 나온다.
- 검증: meta 19개 전부 decrypt → JSON 파싱 성공, encrypt 재적용 시 **원본과 바이트 일치**.
- 원본 meta는 2의 거듭제곱 크기로 `\0` 패딩, 한글패치가 다시 쓴 meta 5개는 패딩 없음(패치 흔적).

## 4. 로더(GSWA2)와 「기동마다 바뀌는 것」

`launch_initialize` → `GSWA2_init` → 그룹별 meta 해독 → `GSWA2_find(name, ?, groupID)`가 타입별로 분기:

| 타입 | 그룹 | 저장 형식 | 로드 방식 |
|---|---|---|---|
| 0 스프라이트 | 2-2, 2-3, 3, 7, 8, 9, 14, 15 | zlib(RGBA 서피스) | 메모리에서 `sprite_create_from_surface` (키 = 파일명에서 `.`/`(` 앞까지) |
| 1 GRID/JSON | 4, 5-2, 5-3, 5-4 | zlib(`ds_grid_write` hex / JSON 문자열) | 메모리 |
| −1 LEGACY | 5-1, 10, 11, 12 | zlib(원본 파일 .txt/.dat) | **`temp_dir`에 풀어 쓴 뒤 파일로 읽음** |
| 2 오디오 | 6-1~6-3, 13 | OGG 원본 | **`temp_dir`에 풀어 쓴 뒤 FMOD로 읽음** |

- LEGACY·오디오 추출 파일명 = `md5_string_unicode(random(1000000))` + 원래 이름 접미 → **기동(과 로드)마다 다른 이름**. 실측: `%LOCALAPPDATA%\fmw_dosd\temp\`에 날짜가 제각각인 해시 이름 파일 24,218개(4.0GB)가 누적.
- 정리 루틴 `GSWA_clear`는 `SBDJ_control` Other_3(게임 종료 이벤트)에서만 불린다 → 강제 종료·크래시 때마다 찌꺼기가 남는다. **이 폴더는 게임을 끈 상태에서 통째로 지워도 안전**(다음 기동 때 다시 풀어 씀).
- 즉 「코드가 바뀐다」의 실체는 ①이 temp 파일 이름, ②(추정) GM 러너는 변수를 힙에 잡으므로 치트엔진 주소가 매 기동 달라지는 것 — 둘 다 `data.win`의 코드 자체와는 무관하다.
- 개발용 경로: `global.isArXiv=false`면 아카이브 대신 `data{ID}/` 폴더에서 평문 파일을 찾는다(`GSWA2_find` 후반). 코드상 이 플래그는 `launch_set_test`에서 1로 고정.

## 6. 모드 적용 관점

### 6-1. 데이터 모드 (텍스트·수치·이미지·음악) — 지금 도구로 가능
- 경로: `gswa.py dump` → TSV 수정 → ds_grid 재인코딩 → zlib → 블롭 교체/추가 → meta의 `DATFILE/POSITION/SIZE` 갱신 → `gmcrypt.encrypt`.
- 게이트: GRID 904개 전부 «해독 → 재인코딩» 바이트 일치(원본 GRID는 끝에 `\0` 1바이트, 패치본은 없음 — 둘 다 로드됨).
- `data.win`을 건드리지 않으므로 **한글패치와 공존 가능**. 단 한글패치가 이미 바꾼 블롭(data4·5-x)을 고치면 한글패치 갱신 시 덮인다.
- 남은 일: `gswa.py pack`(재패킹) 구현 + 실기 확인.

### 6-2. 코드 모드 (메커니즘·버그픽스) — `data.win` 수정 필요
- `%LOCALAPPDATA%\fmw_dosd\mods\`(45개 토글 JSON: BugFixes·Mechanics·QoL·Visual…)와 `addOns\`(data4/data5-4 덮어쓰기 JSON 113개)가 남아 있다. **현재 `data.win`·exe 어디에도 이 폴더를 읽는 코드가 없다**(`addOns` 문자열 0건) → 2026-01-30에 설치했던 커뮤니티 모드판 `data.win`의 흔적이고, 3/1 Steam 업데이트와 5/29 한글패치가 `data.win`을 덮어 **지금은 전부 비활성**.
- 즉 모드판 `data.win`과 한글판 `data.win`은 양자택일. 둘 다 쓰려면:
  1. 한글패치의 `data.win` 변경분 = 폰트 + 하드코딩 문자열 90개 → 이걸 모드판 `data.win`에 이식하거나,
  2. 모드의 코드 변경을 한글판 `data.win`에 이식(모드가 GML 소스/UTMT 스크립트로 배포되면 이쪽이 쉬움).
  - 어느 쪽이든 원본 영어판 `data.win`이 있어야 «패치가 바꾼 것»을 정확히 뽑을 수 있다(현재 로컬엔 한글판만 있음 → Steam 「파일 무결성 검사」로 받되 **한글판 백업 먼저** — `orig/`에 이미 복사해 둠).

### 8-3. 한글판과의 호환성 결론
1. **xdelta를 한글판 data.win에 바로 걸면 안 된다.** 원본 크기부터 다르다 → Delta Patcher가 실패하거나(체크섬), 억지로 적용하면 깨진 파일이 나온다.
2. 반대로 모드판 data.win을 쓰면 **한글 폰트가 사라진다**(모드판은 영어판 폰트 = 한글 글리프 0) → 한글 대사가 전부 빈칸/두부. 대사 자체는 `data/`·`meta/`에 있어서 그대로 남는다.
3. 그래서 **병합 = 「영어 1.2.4 + 모드 xdelta」로 만든 data.win에 한글패치의 data.win 변경분을 이식**:
   - FONT 7종(Noto Sans CJK KR, 한글 11,172자) + 그 글리프 텍스처 페이지(TXTR/TPAG)
